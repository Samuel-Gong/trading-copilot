# 核实部署机器选股命中

用户说“0916 有没有选出摩尔线程”这类话时，默认要求核实当前部署机器上的结果。仅在用户明确指定本机时改用本地数据；本地开发数据的日期或缺失情况不能代替部署机器的证据。

## 查询步骤

1. 从上下文确定股票、交易日期和策略范围，用部署实例的证券信息核对代码及名称。日期补全为北京时间的完整交易日期并在答复中写明；年份有实质歧义时先确认。沿用上下文指定的策略；未指定时先核查部署实例可查询的策略，并说明实际覆盖范围。
2. 阅读仓库根目录的 [生产运维文档](../../../docs/ucloud-production.md)，结合已有连接配置确认当前实例、运行版本和实际数据目录。优先复用已授权的远端 API 或 SSH 只读访问；连接信息缺失时才询问。凭据仅用于对应实例认证，不写入输出或仓库；网络访问遵守项目代理约定。
3. 优先查询目标日期已保存的选股结果、运行记录或命中记录，核对策略标识、参数、结果日期及记录覆盖范围。需要定位存储或接口时，沿部署版本对应的 `backend/app/api/screener.py`、`backend/app/services/strategy_cache.py` 和相关调用链查找；检查接口是否会写入缓存或触发计算，再选择只读路径。当前缓存不自动代表历史结果，盘中曾命中与收盘入选分别说明。
4. 没有足够历史记录时，可在不会改变生产状态的前提下，用部署机器的数据和既有策略计算逻辑做限定日期的只读核算。确认历史窗口完整、输入截止于目标交易日，并说明采用的策略版本与参数是否对应当时。无法保证只读或数据充分时，报告具体缺口；不因查询而启动另一个应用进程、刷新生产缓存、补数、部署或修改策略。

## 证据与结论

- **已选出**：存在目标日期、目标股票的实际命中记录，列出命中策略及可用的时间或排名。
- **未选出**：已检查所述策略范围的完整目标日期结果且未命中；说明核查范围。只有部分记录时，仅对已核查部分给结论。
- **重算符合／不符合**：历史数据核算的结果，明确其不能证明当天实际运行或选出。只有当前参数可用时，明确是按当前参数重算。
- **无法确认**：远端不可访问、日期不覆盖或记录不完整。说明缺失证据，不能用本地结果或空记录得出“未选出”。

答复先给结论，再简述完整日期、股票名称及代码、策略范围和部署机器上的证据来源。只呈现与问题相关的最少数据，不将真实策略、持仓、凭据或原始数据写入 Issue、PR 或提交。
