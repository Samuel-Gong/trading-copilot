# 如何维护持仓并完成每日复盘

**最后更新：** 2026-08-13

**适用版本：** 当前主分支

**预计用时：** 首次配置约 5 分钟，日常复盘时长取决于策略候选、持仓数量和 AI 响应速度

本指南适合希望用交易流水还原历史持仓、并按交易日保存复盘记录的用户。持仓模块是本地研究账本，不连接券商，也不承担现金、公司行动或券商对账职责。

## 开始前

请先确认：

- 已在“设置 → 凭据与能力”完成数据源配置，并至少同步过目标股票或 ETF 的日 K。
- 如需生成大盘、策略候选和多 Agent 报告，已在“设置 → AI 设置”配置可用模型。
- 如需先核对分析角色和 Prompt，可打开“设置 → 分析 Agent”。该页面只展示定义，不会启动复盘。
- 持仓代码使用标准格式，例如 `600519.SH`、`000001.SZ` 或 `430047.BJ`。

## 可选：建仓前维护观察池

“观察池”保存当前未持仓、但可能建仓的 A 股或交易所 ETF。它不记录数量、成本、目标价或收益预期，也不会进入每日复盘的持仓范围。

1. 打开左侧“观察池”，输入代码或名称，从联想结果中选择标的。
2. 选中后，系统把标的加入观察池，同时加入自选。Free 档实时行情和现有监控流程因此可以继续消费同一标的。
3. 在观察标的行点击“添加监控”，选择需要关注的信号并保存。已有规则时，可以继续添加另一条规则。
4. 不再观察时，点击移出。该操作只删除观察状态，保留自选和已经配置的监控规则。

任一账户形成该标的的非零持仓后，系统自动把它移出观察池。平仓后不会自动重新加入；如需继续观察，应由用户再次加入。当前持仓标的不能加入观察池，接口会返回冲突提示。

## 第一步：创建持仓账户

1. 打开左侧“持仓”。
2. 输入账户名称，例如“主账户”或“长期观察”，然后创建账户。
3. 可以建立多个账户。同一标的在不同账户中的交易分别回放，会作为独立持仓进入每日复盘。

只有没有交易记录的账户可以删除。即使某账户已经清仓，历史交易仍存在时也必须先逐笔删除，避免误删历史事实。

## 第二步：记录交易

1. 选择一个账户，点击“记录交易”。也可以在已有持仓行直接点“买入”或“卖出”。
2. 输入代码或名称并从联想结果中选择标的，填写交易日、方向、数量、成交价、手续费、税费和可选备注。交易日只能选择本地已有行情的交易日。
3. 保存后，在页面右上角选择任意可用交易日。页面会重新回放不晚于该日期的全部交易。

交易支持 A 股和交易所 ETF，不支持指数。数量必须大于 `0`，成交价、手续费和税费不能为负数。每次保存都会新增一笔交易，不会覆盖同一标的的旧记录。卖出数量不能超过交易日在该账户中的可用数量；补录历史卖出时，系统还会验证它之后的交易是否仍然有效。

旧版本中直接保存的持仓会在首次读取时自动转换为一笔“期初买入（迁移）”交易。原账户、标的、数量、平均成本、参考买入日期和备注都会保留；迁移前的原始文件会另存为 `portfolio.pre-trade-ledger-v1.json`，且已有备份不会被覆盖。

### 如何理解估值

系统读取不晚于所选日期的最近一条本地收盘价，最多向前查找 365 天：

- 买入批次单位成本 =（成交金额 + 手续费 + 税费）÷ 数量。
- 剩余持仓按 FIFO 扣减最早买入批次，平均成本由剩余批次重新汇总。
- 单条持仓市值 = 数量 × 最近可用收盘价。
- 单条浮动盈亏 = 市值 − 成本。
- 已实现盈亏 = 卖出净收入 − FIFO 被卖出批次成本；卖出手续费和税费从净收入扣除。
- 汇总收益率只使用有价格的持仓，分母是这些持仓对应的成本。

持仓页的“现价”显示本次估值实际使用的本地收盘价，价格下方同时标明日期。如果所选估值日没有同日价格，普通持仓快照会使用估值日前最近的收盘价，并用黄色标记“滞后”。如果估值日前 365 天内完全没有价格，该持仓仍会显示，但不会计入市值、浮动盈亏和汇总收益率；只有发生缺价或价格滞后时，页面才显示汇总提示，避免把缺失数据误当成零。

## 第三步：为持仓设置价格监控

持仓表的“价格监控”列会逐支显示止损价和可选的加仓价。没有启用止损规则的证券会标记为“设置止损”，页面同时汇总尚未完成设置的证券数量。

1. 在持仓行点击“设置止损”或已有价格区域。
2. 填写止损价。止损价必填，连续竞价时段的分时最新价小于或等于该价格时触发重要告警。
3. 如需关注回落加仓价，再填写加仓观察价。加仓价必须高于止损价；连续竞价时段的分时最新价小于或等于该价格时触发警告。留空保存会删除该证券已有的加仓规则，不影响止损规则。
4. 选择通知渠道并保存。站内提醒始终启用；飞书或企业微信需要先在设置中配置。

保存后，规则进入现有监控引擎，并同步显示在“监控中心”。同一证券代码在多个账户中共享这组价格规则；规则不随历史持仓日期复制，也不会改写交易流水或成本。每条规则对同一证券触发后进入 24 小时冷却期。

止损规则如果在监控中心被停用，持仓页会重新标记为待处理。再次从持仓页保存会启用止损规则。系统不会根据成本价或现价自动生成止损价，已有持仓需要逐支设置。

止损价和加仓价都以连续竞价时段的分时最新价判断，依赖实时行情轮询和监控能力。持仓页展示的“现价”仍是所选估值日的本地收盘价，只用于市值和浮动盈亏计算，不参与价格监控触发。

## 第四步：从持仓发起个股分析

在历史持仓行点击“分析”。系统会复用“个股分析”的同一套 K 线、关键价位、AI 流式生成、报告保存和全局分析浮层，同时加入所选日期的账户、数量、FIFO 成本、最早剩余买入批次、估值和备注作为上下文。行情和可用财务数据都使用页面当前选择的截止日。

持仓上下文只帮助报告说明当前研究对象的成本位置和数据风险，不会改变安全边界：报告不输出买卖指令、仓位建议或收益承诺。

## 第五步：生成每日复盘

1. 打开左侧“每日复盘”。
2. 确认或选择交易日。页面默认使用本地 enriched 数据覆盖的最近交易日；周末、节假日和本地没有 enriched 数据的日期不可选。
3. 如需调整候选策略，先到“选股”页通过右上角“策略池”选择股票日线策略。每日复盘会显示本次将使用的策略数量；策略池为空也是有效输入，结果为零候选。
4. 点击“新建复盘”。
5. 页面会自动选中新实例并轮询，直到所有章节完成、明确失败、被前置步骤阻塞或被手动中断。

启动时，系统先把交易账本回放到业务日期，再冻结账户、派生持仓、FIFO 成本和估值范围。复盘市值和浮动盈亏只使用业务日期当天的本地收盘价；当天缺价的持仓保持可见，但不会回退到更早价格，也不会计入市值、浮动盈亏和汇总收益率。此后补录或删除交易不会改写已经生成的档案。

同一交易日可以多次复盘。每次点击“新建复盘”都会创建独立运行实例，并按当天的创建顺序标记为“第 1 次”“第 2 次”等；实例分别冻结策略池、持仓、新闻证据、报告和研究 Graph，不复用同日另一轮的输出。页面左侧“复盘历史”按交易日归组展示全部实例，点击任意实例即可查看它的流程和详细结果。日期选择器只决定下一次新建复盘使用的业务日期，不会切换或改写已选中的历史实例。

复盘严格按三步执行，前一步成功后才启动下一步：

1. **市场环境**：复用现有大盘复盘流程，加入截至复盘日的新闻证据，给所有目标提供共同背景。
2. **策略候选**：冻结启动时“选股”页策略池中的股票日线策略 ID 和名称，使用当前最新的策略代码和参数，在复盘日的历史行情上运行。候选先按命中策略数量降序，再按 `Σ(1 ÷ 策略内排名)` 降序，最后按证券代码升序，最多冻结 8 个。页面展示每个候选命中的策略、策略内排名、排名贡献和策略原始分。系统不保存历史策略版本，因此这是“当前策略的历史回看”。
3. **持仓分析**：展示冻结持仓与复盘日收盘价；持仓和策略候选共用同一套多 Agent 研究 Graph，最多并发分析三项目标。

每个目标的 Graph 都是实际执行状态,不是静态示意图:

1. “研究事实”节点装配截至业务日期的 K 线、技术指标、关键价位、目标身份、公告日合规的财务材料和发布时间合规的新闻证据。
2. Market、Sentiment、News 和 Fundamentals 四类 Analyst 并行研究。News Analyst 只能读取档案中冻结的新闻；某类材料缺失时,对应节点记录数据缺口,不使用常识补写事实。
3. Bull Researcher 与 Bear Researcher 进行两轮交替辩论：`Bull₁ → Bear₁ → Bull₂ → Bear₂`。每次发言都会读取完整历史并直接回应对方上一轮观点。四次发言全部完成后，Research Manager 才裁决共识、分歧和证据等级。
4. Trader 把裁决整理成后续研究观察方案。它不生成买卖或仓位动作。
5. Aggressive、Conservative 和 Neutral 三类 Analyst 审查风险,Portfolio Manager 汇总最终研究结论。流程到此停止,不进入 Execution。

页面顶部显示当前阶段、完成比例和正在运行的节点。数据进入运行中节点时,对应边会显示流动粒子；完成、失败和阻塞使用不同的边状态。点击任一节点后,页面分区展示:

- “收到的输入”：冻结字段、事实摘要和可点击的上游节点摘要。Bull、Bear 和 Research Manager 还会显示当前轮次、上一发言方和已完成发言数。
- “生成的输出”：节点摘要和按 Markdown 标题拆分的结构化章节。
- “完整多空辩论记录”：逐项显示轮次、发言方、逻辑发言序号、模型尝试次数、回应的上一轮观点和本轮输出。
- “动态记录”：本节点最近的开始、完成、失败或恢复事件。

最终报告来自 Portfolio Manager。所有节点都遵守“不输出买卖、仓位、目标价或其他交易执行指令”的安全边界。

### 查看 Agent 配置

打开“设置 → 分析 Agent”可查看静态拓扑。点击节点后,页面显示该节点是否调用模型、实际 System Prompt、User Prompt 模板、必需或可选输入及要求输出的 Markdown 章节。设置页与运行态读取同一份后端 Graph 定义,但设置页不会执行 Agent,当前也不提供 Prompt 编辑。

### 历史日期如何避免未来信息

所有可变事实统一使用复盘日作为截止线：

- 交易只回放 `trade_date <= 复盘日` 的记录。
- 日 K、指数、技术指标和时序扩展数据只读取不晚于复盘日的数据。
- 财务数据按公告日期截断；财务表没有公告时间时，历史复盘宁可显示缺失，也不注入当前快照。
- 新闻按 `published_at` 截断到北京时间复盘日 `23:59:59`；未来新闻和发布时间未知的新闻都不会进入大盘报告或任何 Agent Prompt。
- 没有生效日期的当前概念、行业 snapshot 不进入历史大盘上下文。

页面“市场环境”步骤会显示新闻截止时间、条数、来源抓取状态和实际新闻标题，便于核对。如果新闻源暂时不可用，复盘仍会继续，并只使用本地归档中满足截止条件的新闻。

## 处理部分失败和服务重启

市场环境失败或中断时，策略候选和持仓分析不会启动；策略筛选或任一候选 Graph 未完成时，持仓分析也不会启动。后续步骤会显示“前置阻塞”，用于区分“尚未运行”和“自身运行失败”。同一阶段内的多个候选或持仓仍可并发分析，单个目标失败不会取消同阶段已经完成的兄弟目标。

点击“重试失败项”时，系统会重新提交全部失败或中断章节。若只希望恢复一个分析目标，请在 Graph 中选择失败或中断节点，点击“从此节点恢复”：

- 已完成报告的引用保持不变，不重复调用模型。
- 普通节点恢复只重跑所选节点及其依赖下游；已完成的兄弟 Agent 作为 checkpoint 保留。
- Bull 或 Bear 在某轮失败时，系统保留此前成功发言和本次失败记录。恢复会重试当前逻辑发言，再继续剩余辩论和 Research Manager；不会重跑四类 Analyst，也不会删除已经完成的辩论历史。
- 候选 Graph 恢复成功且候选阶段全部完成后，系统会自动解除持仓步骤的前置阻塞并继续执行，不需要再次点击整单重试。
- 报告必须同时匹配复盘实例 ID 和 `账户 ID:证券代码` 才能复用；同日另一轮复盘、另一账户或普通个股报告不会误挂载。
- 服务重启后，遗留的等待中或运行中任务会转为“已中断”，用户可以继续精准重试。

只要有任意每日复盘仍在运行，页头会显示“中断全部（N）”。点击后会取消所有交易日、所有实例中正在执行或等待执行的每日复盘任务，包括市场环境、策略筛选以及候选和持仓的 Agent 子任务；已完成节点继续作为 checkpoint 保留，尚未结束的步骤和节点转为“已中断”。随后在历史导航中选择具体实例，点击“从中断处继续”即可恢复该实例。该操作只影响每日复盘任务，不会停止行情同步、回测或其他模块的任务。

## 数据位置与备份

所有数据保存在配置的 `DATA_DIR/user_data/` 下：

| 文件 | 内容 |
| --- | --- |
| `portfolio.json` | schema v4 观察池、账户与买卖交易流水；历史持仓由交易回放得到 |
| `monitor_rules/*.json` | 监控中心和持仓页保存的价格、信号、市场与策略规则；持仓止损和加仓各占一条规则 |
| `watchlist.parquet` | 自选标的；加入观察池时同步写入，移出观察池或建仓时不会自动删除 |
| `portfolio.pre-trade-ledger-v1.json` | 首次迁移旧版持仓前保留的原始 JSON；仅在检测到旧版 `positions` 时创建 |
| `review_news.json` | NewsNow 新闻本地归档，查询时按发布时间截断 |
| `daily_reviews.json` | 按业务日期冻结的复盘档案、策略候选、Graph 节点状态、结构化输入输出、事件和报告正文快照 |
| `ai_market_recaps.json` | 大盘复盘报告正文 |
| `ai_stock_reports.json` | 普通、持仓和每日复盘的个股报告正文 |

写入使用临时文件替换，避免进程中断留下半份 JSON。每日复盘会在共享报告 ID 之外保存正文快照，因此共享报告历史被裁剪后，档案仍可阅读。备份或迁移时仍应复制整个 `DATA_DIR`，以同时保留普通分析历史、行情数据和配置。

## 常见问题

### 记录交易时提示代码无效

确认代码使用六位数字和交易所后缀，并且本地证券维表中存在该标的。先运行盘后数据管道，再重试记录交易。

### 持仓显示缺价

先确认日 K 已同步到所选日期。缺价不会阻止标的进入冻结范围和 AI 分析，但该项不会进入市值及盈亏汇总。

### 每日复盘一直显示生成中

先刷新页面。若服务曾重启，任务会显示“已中断”；可以在 Graph 中从具体节点恢复，也可以点击“重试失败项”恢复全部失败项。若仍失败，查看节点错误，并检查数据源、AI 配置和本地日 K。

### 为什么补录交易后旧复盘没有变化

这是预期行为。每日复盘保存的是启动时的冻结范围，目的是让历史记录可解释。持仓页的历史快照会立即重算，但已经生成的复盘档案不会被静默改写。

## 明确不包含的能力

当前版本不自动导入券商成交，不管理现金，不处理分红、拆股、配股、转托管或外汇，也不自动下单。系统会按手工录入的费用计算研究口径成本和已实现收益，但这不等于券商对账结果。

每日复盘和个股分析仅用于学习与研究，不构成投资建议。
